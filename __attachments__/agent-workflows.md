# Тест-кейсы: агентские workflow домена

> Проверка конвейера: `project-glossary-writer` → create-скиллы → `domain-qa-engineer` → `domain-documentation-writer`, включая remediation-пути, скоупы, гейты и СТОП-каскады.

## Подготовка (общая)

- **Ветка изоляции:** `git checkout -b test/agent-workflow` — весь мусор откатывается одной командой (`git checkout main && git branch -D test/agent-workflow`).
- **Реальные «жертвы»** (без создания мусора в домене):
  - `locale.ts` — VO **без записи в глоссарии** (исходник и тест существуют) — кейсы remediation/glossary-first.
  - `rating.ts` — для дрейф-теста (глоссарий правится руками, потом откат).
  - Фиктивный термин «Закладка» (`Bookmark`) — для резервирования и переименования (создаётся и откатывается через ветку).
- Перед каждым кейсом: `git status` чистый. После — сверять затронутые файлы.

## F. Permissions / негативные

- **F1 — Зона поражения:** после каждого кейса `git status` — агент тронул только свою зону:
  | Агент | Разрешённая зона |
  |---|---|
  | `project-glossary-writer` | только `docs/domain/glossary.md` |
  | `domain-qa-engineer` | только `**/*.test.ts` |
  | `domain-documentation-writer` | `docs/domain/**/*.md` (кроме глоссария) + комментарии в `packages/core/src/domain/**/*.ts` |
- **F2 — Прямой доступ:** `@`-вызов любого агента из главной сессии работает независимо от его `task`-permissions.
- **F3 — Отсутствие циклов:** ни один кейс не должен породить петлю (QA не вызывает QA; глоссарист — лист).
